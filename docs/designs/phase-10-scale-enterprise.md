## Architecture Decisions

- **Bulk import:** `waitUntil()` from Next.js (no new dependency). Upgrade to Inngest
  when import volumes justify it (documented in TODOS.md).
- **Timezone:** Organization-level IANA timezone string. Simpler than per-user; handles
  95% of cases. User-level can be layered on later without breaking changes.
- **Sterling adapter:** Follows `BackgroundCheckAdapter` interface exactly. Sterling
  tokens encrypted at rest using `crypto.ts`. PII never logged (same as Checkr contract).
- **Key rotation:** `tryDecrypt` tries new key first, falls back to old key via
  `CHECKR_TOKEN_ENCRYPTION_KEY_OLD` env var. Re-encrypt migration is a standalone
  script, not a Prisma migration.
- **Shift auto-close:** Calls `shiftService.completeShift()` (not reimplemented).
  Batch limit 500, P2025 handling, CronJobRun recording.
- **Org health score:** Pure domain function in `src/server/domain/org-health.ts`.
  No service or repository — queries piggybacked on existing dashboard stats.
- **Activity feed:** AuditLog query with `orgId` filter, `ORDER BY createdAt DESC`,
  `LIMIT 20`. Curated action types (APPLICATION_SUBMITTED, SHIFT_CHECKIN,
  CREDENTIAL_ISSUED, SHIFT_COMPLETED, MEMBER_INVITED).
- **Email delivery:** Resend webhook with signature verification (timing-safe compare).
  `EmailDeliveryEvent` table with `eventId` unique for idempotency. Follows
  Stripe/Checkr webhook handler pattern exactly.
- **CompanySwitcher:** Mirrors OrgSwitcher component. Shares no code (2 instances
  acceptable). Extract shared `ContextSwitcher` if a third context appears.
- **All new crons:** Follow `credential-expiry-service.ts` pattern: per-record
  try/catch, P2025 handling, transaction-wrapped audit, return summary for
  CronJobRun recording.

## Error Handling Requirements

- **Sterling adapter:** Named error classes: `SterlingAuthError`, `SterlingValidationError`,
  `SterlingRateLimitError` (backoff + 2x retry), `SterlingApiError`. No catch-all.
- **Key rotation:** If neither key decrypts → log error, return null, surface
  "Re-connect Checkr" in UI. Never swallow.
- **Resend webhook:** Invalid signature → 400. Unknown event type → 200 + log.
  Duplicate event → 200 (idempotent).
- **All cron services:** Catch `ConnectionPoolError` specifically, log with alertable
  severity. Don't swallow with generic catch.

## Deployment Sequence

1. `prisma migrate deploy` — additive columns + new tables + indexes (CONCURRENTLY)
2. Deploy app code
3. Register Resend webhook URL in Resend dashboard
4. Add Sterling env vars (if API access obtained)
5. Key rotation: set `CHECKR_TOKEN_ENCRYPTION_KEY_OLD` → rotate primary key →
   run re-encrypt script → verify → remove old key
6. Enable new cron jobs in `vercel.json`

Rollback: git revert (all additive) + disable crons via Vercel dashboard.
Key rotation is semi-irreversible — keep old key until re-encryption verified.

## Plan Amendments (Eng Review 2026-03-19)

- **CREATE INDEX CONCURRENTLY:** Use `prisma migrate dev --create-only` then edit
  generated SQL to use `CONCURRENTLY`. Cannot run inside Prisma's default transaction
  wrapper. Raw SQL migration required.
- **Digest concurrency:** Rely on `lastDigestSentAt` idempotency (already exists) rather
  than advisory lock. Overlapping cron runs are harmless — second run sees updated
  timestamp and skips.
- **Timezone default:** `Organization.timezone` is nullable. NULL = UTC (existing behavior
  preserved). IANA strings handle DST automatically. Org settings page gets timezone dropdown.
- **Hard-bounce policy:** Auto-disable after 2+ hard bounces (not 1). Admin re-enable button
  resets counter. Critical emails (FCRA, billing) are NEVER suppressed regardless of bounce
  status.
- **Key rotation sequence (revised):** Re-encrypt FIRST, swap keys SECOND:
  1. Set `CHECKR_TOKEN_ENCRYPTION_KEY_NEW` env var
  2. Run re-encrypt script (decrypt current → encrypt new, per-record with cursor checkpoint)
  3. Verify all tokens re-encrypted
  4. Swap primary key to new value, set old key as fallback
  5. Remove old key after verification
- **Sterling feature gate:** Env-var-as-gate — `getAdapter('STERLING')` returns null if
  `STERLING_API_KEY` missing. UI shows "Sterling not configured." No FeatureFlag row needed.
- **Sterling error classes (5 total):** `SterlingAuthError`, `SterlingValidationError`,
  `SterlingRateLimitError`, `SterlingTimeoutError`, `SterlingApiError`.
- **Shift auto-close:** Add continuation cursor (like digest) for backlogs > 500.
- **Cron error handling (expanded):** Catch deadlocks, serialization failures, query
  timeouts in addition to connection pool exhaustion. All logged with alertable severity.

## Design Specifications

*Added by /plan-design-review on 2026-03-19. Calibrated against DESIGN.md.*

### CompanySwitcher

**Layout:** Mirrors OrgSwitcher exactly — shadcn `DropdownMenu`, 220px width, `Check`
icon (lucide, forest green) for current company, `Plus` for "Create company."
Positioned in navbar next to OrgSwitcher.

**Typography:** Company name = Geist body (16px, 400). "Create company" = Geist
small (14px), muted-foreground.

**States:**
- 0 companies: "No companies yet" + "Create company" link
- 1 company: Display text, no dropdown
- 2+ companies: Dropdown with check icon on active
- 5+ companies: `max-h-60 overflow-y-auto`
- Loading: Skeleton text
- Error (switch fails): Toast

**Accessibility:** `role="menu"`, `aria-label="Switch company"`. Arrow keys navigate,
Enter selects, Escape closes. 44px min touch targets.

**Mobile:** Inside hamburger menu (same position as OrgSwitcher).

### Org Health Score Widget

**Position:** Integrated into greeting banner area on dashboard. First visual after
greeting text.

**Layout:** Card with sand-light background (`#E8DCC8`) — matches Getting Started
checklist pattern. Score number + progress bar + actionable tip.

**Typography:** Score = Geist h3 (20px, 600) + "/100" in muted-foreground.
Tip text = Geist body (16px, 400), muted-foreground. Action link = Geist body
(16px, 600), text-primary, underline on hover.

**Progress bar:** `h-2 rounded-full bg-primary` fill, `bg-neutral-200` track.
NOT a circular donut chart (AI slop).

**States:**
- Loading: Skeleton bar + pulsing number
- Score = 0: "Set up your org to get started" + [Start setup →]
- Score > 0: Score + bar + tip ("Publish an opportunity to reach 85")
- Error: Hide widget (non-critical)

**Accessibility:** `role="progressbar"`, `aria-valuenow={score}`, `aria-valuemax="100"`.

**Mobile:** Full width card, score + tip stacked vertically.

### Admin Activity Feed

**Position:** Replaces "Recent Applications" section on org dashboard. Below stat cards.

**Layout:** Card with neutral-100 background (`#F5F4F0`). Events grouped by date.
Small dots (not icon-in-circle). No colored left-border per event type (AI slop).

**Typography:**
- Date headers: Geist small (14px, 600), uppercase, tracking-wide, muted-foreground
- Event text: Geist body (16px, 400)
- Timestamps: Geist small (14px, 400), muted-foreground, right-aligned
- "View all activity" link: Geist small (14px, 600), text-primary

**Dots:** ● = 8px `bg-primary` (today's events), ○ = 8px `bg-neutral-300` (older).

**Curated action types:** APPLICATION_SUBMITTED, SHIFT_CHECKIN, CREDENTIAL_ISSUED,
SHIFT_COMPLETED, MEMBER_INVITED.

**States:**
- Loading: 5 skeleton rows with gray dots
- Empty: "No activity yet. Your org's story starts when you get your first
  volunteer!" + [Create opportunity →]
- Error: Toast "Couldn't load activity" + retry link
- Success: Event list with relative times, grouped by date

**Accessibility:** `role="feed"`, `aria-label="Recent activity"`. Per item:
`role="article"`.

**Mobile:** Full width, same layout (naturally responsive list).

### Email Delivery Dashboard

**Position:** New section on admin health page (`/app/admin/health`), between
cron health and Stripe reconciliation.

**Layout:** 3 StatCards (reuse existing component) + bounce table below.

**StatCards:**
- "Sent": neutral icon, Geist tabular-nums
- "Delivered": success green (`#2D7A4F`) number
- "Bounced": error red (`#B33A3A`) number (only if > 0, otherwise muted)

**Bounce table:** Standard shadcn Table. Columns: Email, Bounce Count, Action.
"Re-enable" button: shadcn `Button variant="outline" size="sm"`.

**States:**
- Loading: 3 skeleton cards + skeleton table rows
- Empty (no emails sent): "No emails sent yet." (EmptyState with Mail icon)
- Empty (no bounces): "No bounces — great!" with green checkmark
- Error: Toast on API error
- Re-enable success: Toast "Email re-enabled for {address}"

**Accessibility:** "Re-enable" buttons: `aria-label="Re-enable email for {address}"`.
Tab-focusable, Enter activates. 44px button height.

**Mobile:** StatCards stacked vertically. Bounce table → card layout per bounce
(no horizontal scroll).

### Timezone Dropdown

**Position:** Org settings page, below existing org fields.

**Component:** shadcn `Combobox` (searchable Select) for IANA timezone list.

**Label:** "Timezone" (Geist small, 14px, 600).
**Default:** "UTC (default)" when Organization.timezone is NULL.
**Save:** Auto-save on selection change. Toast "Timezone saved."

**Mobile:** Native select behavior.

### AI Slop Guards

- Health score: Horizontal progress bar (NOT circular donut chart). Forest green
  fill. No icon-in-circle decoration.
- Activity feed: Small dots + plain text (NOT card-per-event, NOT icon-in-colored-
  circle, NOT colored left-border per type).
- Email stats: Reuse existing StatCard component exactly. Forest green for success.
- Bounce table: Plain text + buttons. No red/green status badges.
- CompanySwitcher: Exact copy of OrgSwitcher pattern. No redesign.

| # | Decision | Choice | Rationale |

| 1 | Health score visual | Horizontal progress bar | Circular gauges are AI slop. Progress bar matches Getting Started checklist. |
