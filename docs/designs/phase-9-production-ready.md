## Vision

VolunteerReady becomes production-ready for real users. A new org signs up,
gets guided through setup, and receives their first volunteer application.
The platform balances reliability (Stripe reconciliation, credential expiry
emails) with activation delight (shift reminders, status timelines, onboarding).

### 10x Check

A self-serve onboarding funnel where a new org configures screener questions
from templates, publishes their first opportunity, and gets their first
volunteer application within 30 minutes. No sales call needed.

## Scope — 13 Deliverables

### Baseline (Hybrid Critical Path)

1. **Product screenshots for marketing pages** — 5 key shots (screener,
   shifts, credentials, ESG, profile) in `public/marketing/` as WebP
2. **Context-switch UI (Org ↔ Company)** — navbar dropdown mirroring
   OrgSwitcher pattern; `company.switchCompany` tRPC mutation sets
   `Session.currentCompanyId`
3. **Credential share token expiry notification email** — 7 days before
   expiry; piggybacks on existing 03:00 UTC cron; `notifiedAt` field
   prevents double-send
4. **Stripe webhook event reconciliation** — admin-triggered tool that
   calls Stripe list events API, compares against `StripeWebhookEvent`
   idempotency table, replays missed events

### Accepted Expansions (cherry-picked)

5. **Shift reminder emails** — 24hr before shift; new cron job (~06:00
   UTC); `reminderSentAt` on ShiftSignup for idempotency
6. **Application status timeline** — visual timeline on volunteer's
   "My Applications" detail page from AuditLog data; restricted projection
   (no metadata/actorId exposed)
7. **Org dashboard "Getting Started" checklist** — persistent widget
   showing onboarding progress; links to next step; dismissable
8. **Email notification digests** — daily/weekly summary; new cron at
   ~08:00 UTC; extends NotificationPreference model
9. **Onboarding wizard** — multi-step guided first-run modal; shares
   state with getting started checklist via `onboardingProgress` JSON
   field on Organization
10. **Bulk volunteer import (CSV upload)** — parse, validate, sanitize
    (formula injection defense), upsert users, send invite emails with
    2/sec rate limiting and cron retry for quota overflow

### Inline Additions (from review)

11. **`reminderSentAt` on ShiftSignup** — idempotency + debuggability
12. **Cron job health dashboard** — admin page showing last-run time
    and result for each cron job
13. **Mobile bulk import guard** — "Use desktop" message on mobile viewport

## Architecture Decisions

- **Cron auth:** Extract `withCronAuth(handler)` wrapper in
  `src/server/lib/cron-auth.ts` — all cron routes use it (DRY)
- **AuditLog index:** Add `@@index([entityType, entityId])` in migration
- **Bulk import queue:** New `BulkImportJob` table (status, progress,
  errorRows JSON) — handles browser disconnect, enables retry, tracks
  partial progress. Service processes rows transactionally.
- **Bulk import rate limiting:** Batch emails at 2/sec with progress
  indicator; queue remaining for cron retry if quota exceeded
- **CSV sanitization:** Reuse formula injection defense from `esg-report.ts`
- **Status timeline security:** Query only `action` + `createdAt` from
  AuditLog — never expose `metadata` or `actorId` to volunteers
- **Feature flags:** Onboarding wizard and bulk import behind flags
- **Shared onboarding state:** Wizard + checklist share
  `Organization.onboardingProgress` JSON field
- **Cron health storage:** New `CronJobRun` table (jobName, startedAt,
  completedAt, status, resultSummary JSON, durationMs) — replaces
  ephemeral logs with queryable history for the admin dashboard
- **Stripe reconciliation:** Chronological replay (oldest-first) with
  advisory lock/mutex to prevent concurrent reconciliation runs;
  reuses existing webhook handler for event processing
- **Timing:** All cron jobs use UTC. Timezone-aware delivery deferred
  to post-Phase 9 (see TODOS.md)

## Design Specifications

*Added by /plan-design-review on 2026-03-19. Calibrated against DESIGN.md.*

### Onboarding Wizard

**Layout:** Centered modal (max-w-lg, p-8) on desktop. Full-screen bottom sheet
on mobile (slides up, step indicator in top bar, buttons pinned to bottom).

**Step indicator:** `● ● ○ ○ Step 2 of 4` — filled dots for complete, open for
remaining. NOT numbered badges. `aria-label="Step 2 of 4"`, `aria-current="step"`.

**Typography:** Step title = Fraunces h2 (32px, 700). Description = Geist body
(16px, 400). "Skip setup" = Geist small (14px, muted-foreground).

**Colors:** Primary buttons = bg-primary (#1B3C2A). Step dots done = bg-primary.
Step dots future = bg-neutral-200 (#E8E6E1).

**Completion:** Animated green checkmark (300ms scale-in, ease-out) + "Your org
is live!" (Fraunces h2) + copyable apply link + "Go to dashboard" CTA. No confetti.

**Accessibility:** `role="dialog"`, `aria-modal="true"`, focus trap, Escape closes
(confirm if fields dirty). Tab order: title → fields → Back → Continue → Skip.

**States:** Loading = skeleton pulses on form fields. Error = red inline text below
failed field + toast for server errors. Step N of 4 shown throughout.

### Getting Started Checklist

**Position:** Replaces the greeting banner on dashboard for new orgs. Banner returns
after wizard complete or checklist dismissed.

**Layout:** Card with sand-light background (#E8DCC8) to differentiate. Items as
list with custom green circle checkmarks (not generic checkbox). Progress bar
(bg-primary) at bottom. Dismiss link (muted) in bottom-right.

**Typography:** Items = Geist body (16px). Next action = bold. Completed =
line-through + muted. Progress = Geist small (14px, 600, tabular-nums).

**Accessibility:** `role="group"`, `aria-label="Setup checklist"`. Progress bar:
`role="progressbar"`, `aria-valuenow`. Dismiss: `aria-label="Dismiss setup checklist"`.

### Application Status Timeline

**Layout:** Vertical timeline inside the application detail page, positioned as a
new Card between "Status summary" and "Submitted answers". Vertical line
(border-l-2 border-primary/20) with colored dots.

**Dots:** Current status = 12px filled circle (bg-primary). Past = 8px
(bg-neutral-300). NOT a stepper component.

**Typography:** Status label = Geist body (16px, 600). Date = Geist small (14px,
muted-foreground). Current status is top (reverse chronological).

**Empty state:** Single dot — "Submitted on {date}. We'll show updates here as
your application progresses." Uses warm tone, not clinical.

**Accessibility:** `role="list"` on container. Each entry: `role="listitem"` with
`aria-label="Approved on March 18, 2026"`. Color is NOT the only indicator.

### Bulk Import

**Layout:** Full page with centered drop zone (max-w-xl). Drop zone uses dashed
border (border-dashed border-2), Upload icon from lucide, p-12 (48px).

**Template CSV:** 3 columns — email (required), firstName (optional), lastName
(optional). "Download template" ghost button below drop zone.

**Progress state:** "Importing volunteers..." + progress bar with count
("247 of 500") + "Sending invite emails (2/sec)".

**Results state:** Green/red/muted stat lines — "✓ 247 created" (text-success),
"─ 50 skipped" (text-muted-foreground), "✗ 3 errors" (text-error). Expandable
error list with row numbers. [View errors] + [Import another] buttons.

**Mobile:** "Use a desktop browser for CSV import" message with laptop
illustration. No upload functionality on mobile.

**Accessibility:** Drop zone: `role="button"`, `aria-label="Upload CSV file"`,
keyboard activatable. Progress: `role="progressbar"`. Error banner: `role="alert"`.
All buttons ≥ 44px touch target.

### Context-Switch Dropdown

**Layout:** Mirrors OrgSwitcher exactly — DropdownMenu, 220px width, Check icon
for current, Plus for "Create company." Positioned in navbar next to OrgSwitcher.

**Empty state:** "No companies yet" + "Create company" link.

**Scroll:** `max-h-60 overflow-y-auto` when 5+ companies.

### Email Templates

All use existing `buildEmailHtml()` (forest green header, warm neutral footer).

- **Shift reminder:** "Your shift is tomorrow" + shift title + time + location +
  "View my shifts" CTA button
- **Credential expiry:** "Your share link expires in 7 days" + credential name +
  org name + "Manage credentials" CTA button
- **Digest:** Weekly by default (per-user preference control). "{N} updates this
  week" + grouped list (applications, shifts, credentials) + "View dashboard" CTA

### Cron Health Dashboard

**Layout:** Admin-only page (`/app/admin/health`). 3 StatCards (reuse existing
component) + recent runs table.

**StatCards:** Job name + "✓ 2h ago" (text-success) or "✗ Failed" (text-error).

**States:** Loading = skeleton cards + table rows. Empty = "No cron jobs have run
yet" (EmptyState with Clock icon).

### Design Decisions Log

| # | Decision | Choice | Rationale |
|---|----------|--------|-----------|
| 1 | Wizard completion | Animated checkmark (300ms) | Warm without being cheesy. Confetti risks AI slop. |
| 2 | Checklist position | Replaces greeting banner | First thing new users see. Banner returns later. |
| 3 | Digest default | Weekly, per-user control | Less intrusive for new product. Users can switch to daily. |
| 4 | CSV columns | email, firstName, lastName | Minimal reduces errors. Users fill own profile. |
| 5 | Mobile wizard | Full-screen bottom sheet | Native mobile pattern. Centered modals feel wrong on small screens. |

### AI Slop Guards

- Wizard: Forest green primary (not blue). Fraunces h2 titles. Left-aligned text.
  Dot indicator (not numbered stepper). No icon-in-circle decorations.
- Checklist: Sand-light background card. Custom green circle marks. Not a generic
  todo list.
- Import: Dashed border drop zone (existing pattern). Upload icon from lucide
  (not generic cloud). Semantic colors for results.
- Timeline: Vertical line + dots (not a stepper component). Current dot larger.

## Deployment Sequence

1. `prisma migrate deploy` — indexes + nullable columns
2. Deploy app (all code)
3. Enable cron jobs in `vercel.json`
4. Enable feature flags: `ONBOARDING_WIZARD`, `BULK_IMPORT`
5. Seed demo org for product screenshots
6. Capture screenshots → commit to `public/marketing/`

Rollback: git revert (all additive), cron disable via Vercel dashboard,
feature flag toggle for wizard + import.
