# Testing — full notes

Moved verbatim from `CLAUDE.md` (2026-09-28) to keep that file under Claude Code's size limit.
`CLAUDE.md` keeps a one-line rule per entry and points here; this file holds the full rationale,
history and the traps each rule was learned from. Read the relevant entry before changing the code it describes.

- **The main Vitest suite runs in `TZ=America/Los_Angeles`, deliberately not UTC** (`vitest.config.mts`, v0.42.0.0). CI runners are UTC, and under UTC calendar-day arithmetic (`setDate(d + 30)`) and fixed-span arithmetic (`now + 30 * 86_400_000`) are indistinguishable — so a test asserting the credential-expiry window is exactly 30 days passed under both, and the DST divergence it existed to catch was invisible. Any new date maths gets its divergence exercised for free; do not "normalise" this to UTC to make a failing date test green, because that test is the one telling you the truth

- **Test files are typechecked separately, and CI gates on both** (v0.42.3.0). `tsconfig.json` excludes `**/*.test.ts(x)` and `vitest*.config.*` so `pnpm typecheck` (application code) stays fast; `pnpm typecheck:tests` (`tsconfig.tests.json`, extends the base config without those excludes) covers the rest and runs as its own CI step. The exclusion had hidden 191 real diagnostics across 39 files — mocks inferred as zero-arg, test fixtures drifted from the domain types they exercise — until this gate was added; do not drop `pnpm typecheck:tests` from CI as "redundant" with `pnpm typecheck`, they check disjoint file sets.

- **Vitest 5** (bumped from 4.1.11 in v0.42.3.0) auto-clears mocks before every test by default; this repo pins `clearMocks: false` explicitly in all three configs (`vitest.config.mts`, `vitest.scripts.config.ts`, `vitest.integration.config.mts`) to preserve the pre-5 behavior, since 177 files use bare `vi.fn()`/`vi.spyOn()` outside `vi.mock()` with no existing `clearMocks`/`resetMocks`/`restoreMocks` convention. Adopting the new default is deliberately deferred — see the P3 TODO in `docs/TODOS.md` — because no mechanical check can catch a test whose assertions silently verify less once mocks stop leaking state across tests in a file; do not flip `clearMocks: true` without also spot-checking mock call-count assertions in the highest-stakes files (background-check consent/disclosure, `OrgVolunteerBlock` roster-block tests).

- Shared tRPC test context: `createMockTrpcContext()` in `src/server/trpc/__tests__/trpc-context-helpers.ts` — extracted at its ~20th hand-built copy (nearly every router `.access.test.ts`) missing `realSession`/`realUserId`/`impersonation`, which `pnpm typecheck:tests` surfaced. New router access tests should use this rather than hand-building a partial context literal.

- E2E tests: Playwright specs in `e2e/` (`pnpm e2e`). Authenticated specs seed a NextAuth database session via `e2e/utils/db.ts` (refuses non-local `DATABASE_URL` unless `E2E_ALLOW_REMOTE_DB=1`); the dev server is the only environment that reproduces Turbopack-dev-only bugs, so bundler-sensitive fixes get e2e coverage.

- E2E cleanup + `fullyParallel`: `playwright.config.ts` sets `fullyParallel: true` (`workers: 1` in CI only), so a spec file's `beforeAll`/`afterAll` run per-worker in separate processes. A spec's `afterAll` must delete only the row IDs its own `beforeAll` created — never an unscoped sweep matching a shared literal prefix (e.g. `startsWith: PREFIX`), which can delete a sibling worker's still-in-use rows mid-test. Prefix sweeps are safe only in `beforeAll`, and only when age-gated (e.g. `createdAt < now - 30min`) so they can't catch a live sibling's fresh rows. See `e2e/esg-dashboard.spec.ts` (`cleanupIds()` vs `cleanupByPrefix()`) and the resolved P0 in `docs/TODOS.md` for the incident this pattern fixes.

- E2E route warmup: `e2e/global-setup.ts` compiles every public route sequentially before the workers start — see the `pnpm e2e` entry above for why. Its route list is **derived** from `PUBLIC_PAGES` (`src/lib/public-pages.ts`) plus `LOCATIONS`, never retyped: the first hand-written draft already omitted `/map` and `/search`, and a route missing here fails as the manifest-race 500 reported against an unrelated page. Adding a public page needs no change here; adding an *authenticated* route does (they are deliberately absent — they need a seeded session).

- E2E layout assertions: `e2e/utils/layout.ts` — `expectNoHorizontalOverflow(page, width)` (document-level, and it names the widest node so a failure is a fix rather than a bisect), `expectNoInternalScroll(page, selector)`, `expectEllipsized(page, selector)`. **All three are different properties; a document-level check alone is necessary but not sufficient.** A `Table`'s own `overflow-auto` wrapper scrolls internally while the document stays exactly the viewport width, and content can break its container yet still stop inside the viewport (`/app/opportunities`' header actions ran 32px past the page padding and ended at exactly 375, so every overflow assertion passed while the button sat flush against the edge). Where a container's bounds are the requirement, assert against the container and measure the widest DESCENDANT, not the wrapper. `expectEllipsized` needs a fixture string with **no line-break opportunities** — underscores and letters, never spaces or hyphens (UAX #14 class BA), or the text wraps instead of overflowing and the assertion passes vacuously. The **768-1023px band is the load-bearing viewport**, not 375px. Consumers: `e2e/staff-tables-mobile.spec.ts` (applications, opportunities, shifts, team) and `e2e/staff-created-volunteers.spec.ts` (the roster).

- Testing the NextAuth callback chain (T15, v0.35.1.0): every other authenticated e2e spec inserts a `Session` row and sets the cookie, which never executes next-auth's callback route — so the claims `src/server/auth.ts` makes about it were verified only by reading `node_modules`. Two seams now cover it, and they are **not interchangeable**. (1) `mintMagicLinkUrl()` in `e2e/utils/db.ts` writes the hashed half of a `VerificationToken` — `sha256(rawToken + NEXTAUTH_SECRET)`, since `authOptions` sets neither `secret` nor a per-provider `secret` — so a spec can navigate to the real `/api/auth/callback/email`. It **must** insert through Prisma: `VerificationToken.expires` is `timestamp without time zone`, so a raw-SQL insert of a JS `Date` stores local wall time that Prisma reads back as UTC, and the token arrives pre-expired west of UTC while silently passing east of it. Bypassing the Resend send is deliberate, not convenience — `RESEND_FROM_EMAIL` is the shared `resend.dev` sandbox sender and the local key is live, so driving `/api/auth/signin/email` would mail real addresses from a test run. (2) `src/server/auth-account-linking.integration.test.ts` calls next-auth's real `callbackHandler` with the real `PrismaAdapter`, because Google cannot be driven over HTTP at all (provider endpoints come from Google's discovery document and the token exchange is server-side, with no seam to redirect without a production-code change). It deep-requires `core/lib/callback-handler.js`, which is **not** in next-auth's `exports` map — accepted so those claims are tested rather than asserted, and a version bump that moves the file is supposed to break it. **The e2e half cannot substitute for the integration half:** on the email branch `callbackHandler` calls `updateUser` too, so only the oauth branch distinguishes `events.signIn` from `events.updateUser` — the whole point of the SECURITY note at `auth.ts:143`. Any negative assertion there ("never calls X") is paired with a contrast test proving the same spy fires on the other branch, or it passes vacuously.
