# Pricing copy and legal/consent disclosure — full notes

Moved verbatim from `CLAUDE.md` (2026-09-28) to keep that file under Claude Code's size limit.
`CLAUDE.md` keeps a one-line rule per entry and points here; this file holds the full rationale,
history and the traps each rule was learned from. Read the relevant entry before changing the code it describes.

- **Pricing copy derives from the plan gates, and there are TWO plan ladders** (v0.41.1.0). `PLAN_FEATURES` in `server/domain/billing.ts` is the single source both pricing surfaces read — the public `/pricing` tier cards AND its comparison table, plus the in-app `/app/billing` upgrade cards. It used to be two lists (cards derived from `getPlanLimits`, table hand-typed) and they disagreed in production. **A field in `PlanLimits` means a service refuses on it.** `maxOpportunities`, `maxMembers` and `canMatching` were deleted because nothing outside the two pages advertising them ever read them, so a Free org could create unlimited opportunities, invite unlimited members and use the matching engine while both surfaces said otherwise; the caps were dropped rather than retro-fitted onto orgs who signed up without them. Four rules, three of which were bugs first: (1) **`planTierProcedure` reads `Organization.planTier`; `companyScopedProcedure({ minPlanTier })` reads `CompanyAccount.planTier`.** Different table, different customer, different price list. `canESGReports` sat on the ORG tier with zero org-side enforcement, so four surfaces sold nonprofits a Pro upgrade that would never have delivered ESG reporting — it belongs to a company sponsor account, sold through the corporate band. `GATED_SURFACES` in `plan-features.guard.test.ts` carries `scope: 'ORG' | 'COMPANY'` and a COMPANY-scoped gate may not appear on the org tier table. (2) **A plan row cannot express "is it switched on yet".** The roster CSV export is free on every plan by design AND behind `staff_created_volunteers` (`defaultEnabled: false`), so the route 404s outside the pilot; `PlanFeature.note` carries that caveat onto every surface, and the guard binds it to the flag's real default so it self-deletes at GA instead of becoming the next stale claim. (3) **"What this upgrade buys" is not "rows introduced at this tier"** — a `detail` can improve without crossing a boundary, which is how STARTER→PRO lost the shift-template increase from its own pitch. Use `getPlanUpgrade(from, to)`. (4) **The guard scans wide and strips comments first.** It reads all of `app` + `server` because `requireCompanyAccess({ minPlanTier })` is callable from a Server Component, and it strips comments because `billing.ts`'s own docstring example otherwise self-reports as an undeclared gate — line comments before block comments, the same ordering `error-disclosure.guard.test.ts` had to learn. Mutation-verified in every direction. The wider lesson, and the one that generalises past pricing: **when marketing copy and code disagree, the copy is usually the half that is out of date, and nobody finds out until a customer does.** A v0.41 audit of all twelve public pages found thirteen such drifts.

- **Disclosure surfaces derive from the definition, never a hand-maintained copy** (v0.37.2.0). When a legal or consent surface enumerates something the code defines — the `/privacy` third-party table, `/terms` §6, roster-relationship copy — bind it to that definition so a new member is a **type error or a red test**, never a silently incomplete disclosure. Two shapes: a `Record` over the union where the surface is keyed like one (`MY_ORG_RELATIONSHIP_COPY`, `ORG_VOLUNTEER_SOURCE_COPY`), or a test that iterates the enum where it is not (`src/app/(public)/privacy/page.test.ts` walks `BackgroundCheckProvider` — the same enum `registry.ts`'s `getAdapter()` switches on — and fails if a provider that can receive SSN and date of birth has no disclosure row). This exists because the un-derived form failed twice: `/privacy` and `/terms` named Checkr as the only background-check provider from launch while Sterling was live and receiving the same PII, and `/terms` §6 told volunteers to dispute FCRA results with the wrong consumer reporting agency. Both were caught by a person reading a page against the source, which does not repeat. Do NOT address this class with a "remember to check the legal pages when changing a capability" rule — the Sterling gap had no capability change to trigger on, so such a rule would not have fired.
